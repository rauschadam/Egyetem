AVL fák

A bináris keresőfák műveletei a fa magasságával arányosak; az AVL fa ezt úgy tartja \(\Theta(\log n)\)-en, hogy minden csúcsban legfeljebb 1 lehet a két részfa magasságkülönbsége.

Definíció, forgatások, beszúrás
AVL fa, egyensúly, jelzőkelmélet

Definíció. Az AVL fák (Adelszon-Velszkij és Landisz, 1962) magasság szerint kiegyensúlyozott bináris keresőfák: a \(t\) fa kiegyensúlyozott (KBF), ha minden \(*p\) csúcsára \(|h(p\to right) - h(p\to left)| \le 1\).

  • A csúcsban tároljuk az egyensúlyát: \(p\to b := h(p\to right) - h(p\to left) \in \{-1, 0, +1\}\).
  • Jelzők: = ha a két részfa egyforma magas, - ha a bal eggyel magasabb, + ha a jobb eggyel magasabb. A levelek jelzője mindig =, ezért ott nem írjuk ki.
  • Ha beszúrás vagy törlés miatt egy csúcs jelzője ++ vagy -- lesz, elromlott az AVL-tulajdonság: javítani kell (forgatással).
  • Tétel: nem üres, \(n\) csúcsú AVL fa \(h\) magasságára \(\lfloor \log n \rfloor \le h \le 1{,}45 \log n\). A keresőfa-műveletek változatlanul érvényesek, csak minden módosítás után ellenőrizzük és szükség esetén helyreállítjuk az egyensúlyt.
Szöveges (zárójeles) jelöléselmélet

Egy fát (bal_részfa gyökér jobb_részfa) alakban írunk le; az üres részfákat elhagyjuk, az olvashatóság kedvéért { }, [ ], ( ) zárójeleket váltogatunk szintenként. A belső csúcsok egyensúlyát az érték mellé írjuk, a levelekét nem.

1. szabály: (++, +) forgatás és tükörképe, a (−−, −)elmélet

Az \(x\) csúcs ++ lett, a jobb gyereke (\(y\)) +. Egy balra forgatás \(y\)-t emeli a gyökérbe, \(x\) lesz a bal gyereke, és \(\beta\) átkerül \(x\) jobb oldalára. A keresőfa-tulajdonság megmarad, mert \(\alpha < x < \beta < y < \gamma\).

⇒

A részfa magassága a forgatás után ugyanannyi, mint a beszúrás előtt volt, ezért beszúrásnál egy forgatás után kész vagyunk. Pointer-állítás: 6 (konstans).

Példa a lapról: a 21 beszúrása után a 15 lett ++, a jobb gyereke (20) +.

⇒
2. szabály: (++, −) dupla forgatás és tükörképe, a (−−, +)elmélet

Az \(x\) csúcs ++, de a jobb gyereke (\(y\)) -: a magasság-növekedés \(y\) bal részfájában, \(z\)-ben van. Most \(z\) kerül a gyökérbe, \(x\) a bal, \(y\) a jobb gyereke lesz; \(\beta\) az \(x\)-hez, \(\gamma\) az \(y\)-hoz kerül (\(\alpha < x < \beta < z < \gamma < y < \delta\)).

Példa a lapról: a 19 beszúrása után a 15 lett ++, a jobb gyereke (27) −, z = 17.

⇒
A beszúrás meneteelmélet
  1. Beszúrjuk a kulcsot, mint egy közönséges keresőfába (új levél, jelzője =).
  2. Elindulunk a beszúrt csúcs szülőjétől a gyökér felé, és javítjuk a jelzőket (bal oldalon nőtt: −1, jobb oldalon nőtt: +1).
  3. Addig megyünk, amíg = nem lesz egy jelző (ott a részfa magassága nem nőtt, kész), vagy ++ / -- nem lesz (forgatunk, és kész), vagy el nem érjük a gyökeret.
  4. Forgatás kiválasztása: ++ csúcs és jobb gyereke + → (++,+); jobb gyereke - → (++,−). Tükrösen: -- és bal gyerek - → (−−,−); bal gyerek + → (−−,+).

Láncolt ábrázolás: Node = { key : T ; b : −1..1 ; left, right : Node* }. A d paraméter azt jelzi, hogy nőtt-e az aktuális részfa magassága.

@AVLinsert(&t : Node* ; k : T ; &d : 𝔹)
switch
  case t = ⊘
    t := new Node(k)
    d := true
  case k < t→key
    AVLinsert(t→left, k, d)
    if d
      leftSubTreeGrown(t, d)
  case k > t→key
    AVLinsert(t→right, k, d)
    if d
      rightSubTreeGrown(t, d)
  case ELSE
    d := false

@leftSubTreeGrown(&t : Node* ; &d : 𝔹)
if t→b = −1
  l := t→left   // t→b−− lenne: −2
  if l→b = −1
    balanceMMm(t, l)
  else
    balanceMMp(t, l)
  d := false
else
  t→b−−
  d := (t→b < 0)

@rightSubTreeGrown(&t : Node* ; &d : 𝔹)
if t→b = 1
  r := t→right   // t→b++ lenne: +2
  if r→b = 1
    balancePPp(t, r)
  else
    balancePPm(t, r)
  d := false
else
  t→b++
  d := (t→b > 0)

A forgatások (t a részfa gyökerére, r / l a jobb / bal gyerekére mutat):

@balancePPp(&t, r : Node*)   // (++,+)
t→right := r→left
r→left := t
r→b := t→b := 0
t := r

@balanceMMm(&t, l : Node*)   // (−−,−)
t→left := l→right
l→right := t
l→b := t→b := 0
t := l

@balancePPm(&t, r : Node*)   // (++,−)
l := r→left
t→right := l→left
r→left := l→right
l→left := t ; l→right := r
t→b := −⌊(l→b + 1) / 2⌋
r→b := ⌊(1 − l→b) / 2⌋
l→b := 0
t := l

@balanceMMp(&t, l : Node*)   // (−−,+)
r := l→right
l→right := r→left
t→left := r→right
r→left := l ; r→right := t
l→b := −⌊(r→b + 1) / 2⌋
t→b := ⌊(1 − r→b) / 2⌋
r→b := 0
t := r

Minimum kivétele és törlés

Törlésnél egy részfa alacsonyabb lesz. A forgatások csökkentik a részfa magasságát, ezért egy forgatás után nem biztos, hogy megállhatunk: a törlés hatása akár a gyökérig is terjedhet.

Minimum kivétele (remMin)elmélet
  1. A gyökértől balra haladunk, amíg lehet. Akinek nincs bal részfája, az a minimum; a címét visszaadjuk.
  2. A minimum helyére (a szülője bal részfájának) a minimum jobb részfája kerül.
  3. A szülő bal részfája rövidült: a jelzőjét növeljük eggyel; ha kell, forgatunk.
  4. Ha a részfa nem rövidült (a gyökerének jelzője nem = lett), kész vagyunk; ha rövidült, a szülőnél folytatjuk.

Az általános törlés segédeljárása: két gyerekes csúcs törlésekor a jobb részfa minimumát emeljük ki.

3. szabály: (++, =) forgatás és tükörképe, a (−−, =)elmélet

Új forgatási séma, csak törléskor fordulhat elő: \(x\) ++ lett, a jobb gyereke (\(y\)) =. Ugyanaz a balra forgatás, mint (++,+)-nál, csak az egyensúlyok mások: \(x\) +, \(y\) - lesz.

⇒

Ez a forgatás nem csökkenti a részfa magasságát (előtte és utána is h+3), így utána nem kell tovább ellenőrizni a jelzőket. A (++,+) és (++,−) forgatás viszont eggyel csökkenti, ezért törlésnél utánuk felfelé folytatni kell.

Megjegyzés a forráshozAz AVL_fa_folytatas.pdf ábráján γ magassága „h−1”, de y jelzője =, tehát β és γ egyforma magas: γ helyesen h+1.

Törlés AVL fábólelmélet

Három eset: levelet, egy gyerekes vagy két gyerekes csúcsot törlünk.

  • Az első kettő összevonható: „ha a törlendő csúcs egyik részfája üres, a másik részfát tesszük a helyére” (akkor is, ha az is üres). A szülő megfelelő oldala rövidült, a jelzőjét módosítjuk.
  • Két gyerekes csúcsnál előbb kiemeljük a jobb részfa minimumát (az ottani kiegyensúlyozás ekkor történik), majd ezt láncoljuk be a törlendő helyére: átveszi a két részfáját és az egyensúlyát. Ezután beállítjuk az új gyökér egyensúlyát, és ha kell, kiegyensúlyozunk.
  • A jobb részfa minimuma nagyobb a bal részfa minden eleménél és kisebb a jobb részfa többi eleménél, így a keresőfa-tulajdonság nem sérül. (A bal részfa maximuma is jó lenne.)
  • Ha a fa egy nagyobb fa része, a magasabb szinteken további kiegyensúlyozások kellhetnek, mert a részfa alacsonyabb lett.

Általános fák

Egy kitüntetett csúcs, a gyökér, és a csúcsoknak tetszőleges sok gyereke lehet. Példák: könyvtárszerkezet, függvénykifejezések.

Ábrázolás két pointerrel, zárójeles alakelmélet

Minden csúcsban két pointer: child1 az első gyerekre, sibling a következő testvérre mutat (esetleg egy harmadik a szülőre). Más ábrázolás is lehet, pl. a gráfoknál használt éllistás.

Node = { child1, sibling : Node* ; key : T } ; Node() { child1 := sibling := ⊘ } ; Node(x) { child1 := sibling := ⊘ ; key := x }.

Zárójeles alak: nem üres fa általános alakja (G t1 … tn), ahol G a gyökér tartalma, t1 … tn a részfák. A fenti fa: { 1 [ 2 (5) ] (3) [ 4 (6) (7) ] }.

Részletes magyarázat: hogyan épül fel a zárójeles alak?

Az alapszabály: minden csúcs egy zárójelpár, és a zárójelen belül először a csúcs kulcsa áll, utána sorban a gyerekeinek részfái: ( gyökér részfa1 részfa2 … részfan ). Minden részfa ugyanilyen alakú (rekurzív jelölés). Egy levélnek nincs gyereke, ezért csak (x).

Felépítés lentről felfelé a fenti fán:

  1. A levelek: (5), (3), (6), (7).
  2. A 2-es csúcs egyetlen gyereke az 5: (2 (5)).
  3. A 4-es csúcs gyerekei a 6 és a 7: (4 (6) (7)).
  4. Az 1-es gyökér gyerekei sorban a 2, a 3 és a 4: (1 (2 (5)) (3) (4 (6) (7))). Ez már a teljes, helyes zárójeles alak.

Mire valók a { } [ ] ( )? Csak az olvashatóságot segítik, a jelentésük ugyanaz. Szintenként váltogatjuk őket, hogy szemmel könnyű legyen összepárosítani a nyitó és záró zárójeleket: a gyökér { }, a gyerekei [ ], az unokák ( ), utána megint { }… Így: { 1 [ 2 (5) ] [ 3 ] [ 4 (6) (7) ] }.

Megjegyzés a forráshozA jegyzet példájában a 3-as körül (3) áll [3] helyett. Ez csak következetlenség, nem hiba, mert a zárójel fajtája nem számít; a nagyobb gyakorlati feladatban már következetesen [ c ] szerepel.

Visszafelé olvasás:

  • A nyitó zárójel utáni első elem a csúcs kulcsa.
  • Utána minden zárójeles csoport egy gyerek részfája, balról jobbra az első, második, … gyerek.
  • A záró zárójel jelzi, hogy a csúcsnak nincs több gyereke.

Például [ 4 (6) (7) ] = „4, két gyerekkel: 6 és 7”; [ 2 (5) ] = „2, egy gyerekkel: 5”.

Miért pont így?

  • A gyökér elöl áll, nem középen. A bináris (AVL) fáknál a (bal gyökér jobb) alakban a hely mondja meg, melyik a bal és a jobb gyerek. Az általános fának tetszőleges számú gyereke lehet, nincs „bal” és „jobb”, csak sorrend; ezért a gyökér elöl van, a gyerekek sorban utána.
  • Illik a két pointeres ábrázoláshoz: a zárójelen belül egymás után következő gyerekek a child1 → sibling → sibling lánc, egy belső zárójelbe lépés pedig a child1 irány.
  • A Zárójelez algoritmus pont ezt írja ki (lásd a 6. feladatot): ( és a kulcs, rekurzívan a gyerekek, végül ). Ezért a kulcsok sorrendje a preorder bejárás: 1 2 5 3 4 6 7.

Két gyors ellenőrzésA nyitó zárójelek száma = a csúcsok száma (itt 7). Egy csúcs mélysége = hány nyitott, még be nem zárt zárójel veszi körül a saját zárójelén kívül (az 5-ös körül a { és a [ van nyitva, tehát a mélysége 2; a gyökéré 0).

Bejárások: a testvéreken érdemesebb ciklussal végigmenni (hatékonyabb), a gyerekek felé rekurzióval. A postorder alakra a bináris fák inorderjére hasonlít, de a függvénykifejezések lengyel formáját adja, ezért hívjuk postordernek.

@preorder(t : Node*)
loop t ≠ ⊘
  process(t)
  preorder(t→child1)
  t := t→sibling

@postorder(t : Node*)
loop t ≠ ⊘
  postorder(t→child1)
  process(t)
  t := t→sibling

@Magasság(t : Node*) : ℤ

  mgy := Magasság(t→child1) + 1
  mt := Magasság(t→sibling)

1. feladatfokszám

Egy d-edfokú B+ fa csúcsaiban 4 bájtos kulcsok és 6 bájtos pointerek vannak. A fát mágneslemezen tároljuk, a blokkméret 4096 bájt. Mekkorának érdemes választani a d fokszámot?

Megoldás

Egy csúcs legfeljebb d−1 kulcsot és d mutatót tartalmaz, és egy blokkba kell férnie:

\[4(d-1) + 6d \le 4096 \;\Rightarrow\; 10d - 4 \le 4096 \;\Rightarrow\; d \le 410.\]

A legnagyobb ilyen egészt választjuk: d = 410.

Ilyen fokszámmal a fa elképesztően alacsony: n = 10⁹ kulcsra a jegyzet szerinti korlát \(\log_{410}(n/409) \le h \le \log_{205}(n/2)\), azaz \(2{,}4 < h < 3{,}8\), tehát h = 3 (négy szint). A felső két szintet megnyitáskor a memóriába töltjük, így egy rekord eléréséhez összesen 3 lemezolvasás kell (ha nincs ilyen kulcs, csak 2).

Megoldás
Saját megoldásA magasság a gyökértől a levelekig vezető élek száma; minden levél h mélységben van. Feltesszük, hogy h ≥ 1 (egyetlen levélnél a felső becslés értelmetlen).

Gráfok ábrázolása

A gráfalgoritmusok egy csúcs feldolgozásakor a szomszédait látogatják meg, ezért az ábrázolásnak ezt kell hatékonyan támogatnia. Itt mindig \(V = \{1, \dots, n\}\), \(n = |V|\), \(m = |E|\).

Definíciókelmélet
  • Gráf: \(G = (V, E)\), ahol V véges halmaz, \(E \subseteq V \times V \setminus \{(u,u) : u \in V\}\). Tehát nincs hurokél és nincs párhuzamos él. V = {} esetén üres gráf.
  • Irányítatlan: minden \((u,v) \in E\)-re \((u,v) = (v,u)\): ábrázoláskor mindkét irányt tárolni kell. Irányított: \((u,v) \ne (v,u)\); a \((v,u)\) az \((u,v)\) él fordítottja.
  • Út: csúcsok \(u_0, u_1, \dots, u_n\) sorozata, ahol minden \((u_{i-1}, u_i) \in E\); hossza n, az élek száma.
  • Szöveges megadás: soronként u → v1; v2. (irányított) vagy u − v1; v2. (irányítatlan, minden él csak egyszer szerepel).
Csúcsmátrix és szomszédossági listaelmélet
  • Szomszédossági (csúcs-) mátrix: \(A/1 : \text{bit}[n,n]\), \(A[i,j] = 1 \iff (i,j) \in E\). Az i szomszédainak bejárása \(\Theta(n)\) (az i-edik sor). Sűrű gráfokhoz (\(m \in \Theta(n^2)\)). Irányítatlan gráfnál szimmetrikus, ezért elég a főátló alatti részt sorfolytonosan egy tömbben tárolni.
  • Szomszédossági lista: \(A/1 : \text{Edge}^*[n]\); A[i] egy fejelem nélküli, egyirányú lista első elemére mutat, amely i szomszédait tartalmazza (Edge = { v : ℕ ; next : Edge* }). A lista kezdőpointere konstans időben elérhető; i szomszédainak bejárása \(O(n)\). Ritka gráfokhoz. A listákat általában csúcs szerint növekvően rendezzük.
1. feladatmátrixból lista

Adott egy irányított gráf csúcsmátrixa az \(A/1 : \text{bit}[n,n]\) mátrixban. Készítsük el a szomszédossági listás ábrázolását a \(B/1 : \text{Edge}^*[n]\) tömbben, csúcs szerint rendezett listákkal! Műveletigény: \(O(n^2)\).

Megoldás
@Csúcsm_szLista(A/1 : bit[n,n] ; B/1 : Edge*[n])
loop i := 1 to n
  B[i] := ⊘
  loop j := n downto 1
    if A[i,j] ≠ 0
      p := new Edge
      p→v := j ; p→next := B[i]
      B[i] := p

Ötlet: az i-edik sorból az i-edik listát építjük. Ha a sort visszafelé (n..1) járjuk, mindig a lista elejére fűzhetünk, és mégis növekvő listát kapunk; nem kell a lista végét nyilvántartani.

Műveletigény: a két ciklus n·n iteráció, az igaz ág legfeljebb \(n^2\)-szer fut: \(\Theta(n^2)\).

5. feladatkülönbséggráf

Adott két irányított gráf ugyanazokkal a csúcsokkal, szomszédossági listával: G1 az A1, G2 az A2 tömbben, a listák csúcs szerint növekvőek. Készítsük el A1-ben a G1 \ G2 gráfot (G1 azon élei, amelyek G2-ben nem szerepelnek), kihasználva a rendezettséget! Műveletigény: \(O(n^2)\).

Megoldás

Ötlet: összefésülés. Az A1[i] listán p, az A2[i] listán q pointerrel haladunk. Három eset: \(p\to v < q\to v\): az él marad, p lép (pe-be mentjük, mert törléshez kell az előző elem); \(p\to v = q\to v\): az élt töröljük A1[i]-ből (ha az első elem, A1[i] módosul!), mindkettő lép; \(p\to v > q\to v\): q lép. Ha bármelyik lista elfogyott, leállhatunk.

@KülönbségGráf(A1/1, A2/1 : Edge*[n])
loop i := 1 to n
  Különbség(A1, A2, i)

pe := ⊘ ; p := A1[i] ; q := A2[i]
loop p ≠ ⊘ ∧ q ≠ ⊘
  switch
    case p→v < q→v
      pe := p
      p := p→next
    case p→v = q→v
      r := p→next
      if pe = ⊘
        A1[i] := r
      else
        pe→next := r
      delete p
      p := r
      q := q→next
    case p→v > q→v
      q := q→next

Készítsük el a szélességi keresést csúcsmátrixos ábrázolásra (A/1 : bit[n][n]), a d és π értékeket a d/1, pi/1 : ℕ[n] tömbökben, color nélkül! Miért nem lenne helyes a d[v] = ∞ helyett a pi[v] = 0 feltételt vizsgálni? Mennyi a műveletigény?

@Huszár(n, m, i1, j1, i2, j2 : ℕ) : ℤ

Veszteségmentes adattömörítés: Huffman és LZW

A forráskódolás azt vizsgálja, adott mennyiségű információ mekkora adattal tárolható. Csak veszteségmentes eljárásokkal foglalkozunk (az adat teljes egészében visszaállítható); bináris esetben a kódszavak a Γ = {0, 1} ábécé feletti szavak (r = 2).

Kód, kódfa, naiv módszerelmélet
  • Kód: Γ feletti véges szavak (kódszavak) nem üres halmaza.
  • Kódfa: a gyökérben az üres szó; egy szó gyerekei a szó után egy karaktert írva kapott szavak, az élek ezzel a karakterrel címkézettek. A kód kódfája a legkevesebb csúcsú ilyen fa, amely minden kódszót tartalmaz. Dekódolás: a gyökértől a bitek szerint lépkedünk, kódszónál kiírjuk a betűt és újrakezdjük.
  • Betűnkénti kódolás: a Σ ábécé betűit egy kölcsönösen egyértelmű Σ → C ⊆ Γ* leképezés kódolja (pl. ASCII).
  • Egyenletes kód: minden kódszó egyforma hosszú. A naiv módszer egyenletes kódot használó betűnkénti kódolás; ha \(|\Gamma| = r\), \(|\Sigma| = d\), a legrövidebb kódszóhossz \(\lceil \log_r d \rceil\).

Huffman-kódoláselmélet

Betűnkénti kódolásnál akkor kapunk rövid kódot, ha a gyakori betűk rövid, a ritkák hosszú kódszót kapnak. A kódfát alulról felfelé építjük a gyakoriságok alapján (r = 2):

  1. Végigolvassuk a szöveget, meghatározzuk a gyakoriságokat.
  2. Minden karakterhez egy csúcs; ezeket egy min-prioritásos sorba tesszük (kulcs: gyakoriság).
  3. Kiveszünk két csúcsot, közös szülőt kapnak; az éleket 0-val és 1-gyel címkézzük a gyakoriságnak megfelelő sorrendben; a szülő a gyakoriságok összegével kerül vissza a sorba. Ismételjük, amíg egynél több csúcs van.
  4. A kódszavakat kiolvassuk a fából, majd a bemenetet újraolvasva betűnként kódolunk.
  • Entrópia: \(H_r(S) = -\sum_{i=1}^{d} p_i \log_r p_i\). Shannon tétele: betűnkénti kódolásnál az átlagos szóhossz \(\ell \ge H_r(S)\). Egy kódolás optimális, ha \(H_r(S) \le \ell < H_r(S) + 1\); a Huffman-kód ilyen.
  • Prefix-kód: egyik kódszó sem valódi prefixe a másiknak, a kódfában minden kódszó levél ⇒ egyértelműen dekódolható.
  • Nem egyértelmű: egyenlő gyakoriságoknál bármelyiket választhatjuk, és a 0/1 szerepe felcserélhető.
  • r > 2: az élek 0..r−1 címkét kapnak, minden lépésben r csúcsot vonunk össze, kivéve az elsőt: ott \(k = d \bmod (r-1)\) csúcsot, ha k > 1, különben k + r − 1-et.
  • A dekódolónak is ismernie kell a kódot: a kódfát / kódtáblát mellékelni kell (rontja a tömörítést), vagy általános gyakoriságokból (pl. a magyar nyelvéből) készítjük a kódot.

LZW (Lempel–Ziv–Welch) szótárkódelmélet

A betűnkénti kódolás hatékonysága korlátos; a szótárkódok egy kódszót egész szavakhoz is rendelnek, kihasználva, hogy a valós adatban rövid részek sűrűn ismétlődnek. Az LZW egy kezdeti (a betűket tartalmazó) kódtáblát bővít lépésről lépésre.

  • Kódolás: a bemenetet egyszer olvassuk; mindig a leghosszabb ismert következő szót (α) keressük. Kiírjuk a kódját, és felvesszük a szótárba az αc szót (c a következő karakter) a következő szabad kóddal.
  • Dekódolás: ugyanabból a kezdeti táblából indul, és ugyanazt a táblát építi fel. Különleges eset: ha a beolvasott kód éppen a most születő (még ismeretlen) kód, akkor a szava \(s + s_1\) (az előző szó + annak első betűje).
  • Hosszú szövegnél a szótárat korlátozzuk (kódszavak száma, szavak hossza, vagy csak a bemenet elején építjük). A kódokat még binárisan is kódolni kell, mégis gyakran rövidebb, mint a Huffman; egyszerű és egy menetben dolgozik.

  x : Item(⟨Σ_i⟩, i) ; D := D ∪ {x}

  c : Σ := In_i
  if dictionaryContainsString(D, s + c)
    s := s + c
  else
    Out := Out + code(D, s)
    if code ≤ MAXCODE
      x : Item(s + c, code++) ; D := D ∪ {x}
    s := ⟨c⟩
Out := Out + code(D, s)
